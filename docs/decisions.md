# 설계 결정 기록

각 항목은 **상황 → 선택 → 이유 → 트레이드오프** 순서다. 날짜는 결정 시점. 계획 단계에 있었지만 실제로 만들지 않은 것은 맨 아래에 따로 적었다.

## 1. 문항은 작업형 한 종류만 — 2026-07-14

**상황.** 원본은 객관식 · 단답 · 서술형 · 실기 · 작업형 다섯 유형을 지원했고, 유형별 응시 UI와 자동채점 로직이 각각 있었다. 정답 노출 사고도 여기서 나왔다.

**선택.** 작업형(슬롯형)만 남겼다. 문항 하나는 슬롯(text · long_text · url · file · number)의 조합이고, 채점은 슬롯별 부분 점수를 사람이 매기거나 export해서 외부에 위임한다. 자동채점 로직은 삭제했다.

**이유.** 인증평가의 실제 문항이 전부 작업형이었다. 쓰지 않는 유형 넷을 유지하는 비용이 정답 관리 위험보다 컸다.

**트레이드오프.** 객관식이 필요한 시험에는 쓸 수 없다. 채점 인력이 필요하다.

## 2. 채점 기준은 서버 밖으로 나가지 않는다 — 2026-07-14

**상황.** 원본은 API가 문항 전체(정답 · 채점 기준 포함)를 내려보내고 클라이언트가 가렸다. 운영자가 안내 문구 칸에 정답을 적으면 그대로 노출됐다.

**선택.** 채점 기준 컬럼을 제외한 응시자 전용 DB 뷰를 만들고, 응시자 경로는 그 뷰만 읽는다. 응시 페이지는 서버 컴포넌트가 페치하므로 클라이언트로 가는 데이터에 채점 기준이 존재하지 않는다. 문항 업로드 파서는 안내 문구와 채점 기준이 같으면 경고한다.

**이유.** "가리는" 방어는 한 번의 실수로 뚫린다. 데이터가 애초에 없으면 실수할 수 없다.

## 3. 세트 단위 감독 스위치 — 2026-07-14

**상황.** 생성형 AI 활용 문항은 응시자가 다른 창에서 AI 도구를 써야 한다. 화면 이탈 감지가 이걸 부정행위로 잡았다.

**선택.** 문제 세트마다 감독 비활성 플래그를 두었다. 켜면 얼굴 감지 · 전체화면 가드 · 이벤트 배처가 내려가고, 화상 스트림은 유지된다. 응시자 화면에는 배너로 알린다. 다른 세트로 넘어가면 자동으로 다시 켜진다.

**이유.** 감독 민감도를 시험 전체로 조절하면 다른 세트의 감독이 약해진다. 세트 단위가 정확한 입도였다.

**트레이드오프.** 감독관은 해당 세트 동안 이벤트 알림 없이 화상만으로 봐야 한다.

## 4. 타이머 3중 방어 — 2026-07-15

**상황.** 브라우저가 백그라운드 탭에서 setInterval을 1분에 1회로 늦춘다. 페이지가 닫히면 자동 제출이 아예 안 된다. 원본은 시작 시각이 비어 있으면 즉시 자동 제출했다.

**선택.**
1. 클라이언트 타이머는 탭 복귀 · 포커스 · 온라인 이벤트에서 `Date.now()` 기준으로 재계산한다. 대기실에서 서버 시각과의 오프셋을 잡는다.
2. 서버의 pg_cron이 매분 만료 세션을 찾아 자동 제출한다.
3. 시험 시작 시각은 시험 단위 절대 시각이라 모든 응시자가 같은 시각에 끝난다.
시작 시각이 비어 있으면 3회 재조회 후에만 자동 제출한다.

**이유.** 셋 중 하나만 있으면 뚫린다. 클라이언트만 있으면 탭을 닫으면 끝이고, 서버만 있으면 화면 표시가 틀리다.

**트레이드오프.** 시간 연장은 세션별 누적 컬럼으로 두고 클라이언트와 pg_cron이 모두 그 값을 반영해야 한다. 한쪽만 고치면 어긋난다.

## 5. 응시자는 인증 사용자가 아니다 — 2026-07-15

**상황.** 응시자는 회당 100명 이상이고, 시험이 끝나면 계정이 필요 없다.

**선택.** 응시자는 관리자가 올린 명단과 이름 + 전화 뒷 4자리로 매칭한 뒤, HMAC 서명된 무상태 쿠키(6시간)로 세션을 유지한다. 응시자용 API는 모두 쿠키의 세션 ID와 요청 본문의 세션 ID가 일치할 때만 응답한다.

**이유.** 응시자마다 인증 사용자를 만들면 계정이 폭증하고 관리가 복잡해진다. 초대 ID로 추적이 가능하므로 계정이 필요 없다.

**트레이드오프.** 이름 + 뒷자리는 약한 인증이다. 신분증 이미지 업로드와 관리자 사후 검토로 보완했다. 초기 계획의 이메일 OTP는 실제 운영에서 불필요해 제거했다.

## 6. 감독관 액션과 채팅 — 2026-07-16

**상황.** 감독관이 시험 중 할 수 있어야 하는 일은 시간 연장과 강제 종료, 그리고 응시자와의 대화다.

**선택.** 액션은 두 종류(연장 · 강제 종료)로 제한하고 사유 입력과 확인 모달을 둔다. 강제 종료는 자동 제출과 구분해 `auto_submitted=false`로 저장하고 사유를 메모에 남긴다. 채팅은 화상 SDK의 메시징 기능 대신 자체 테이블 + Supabase Realtime으로 만들었다. 공지 메시지는 응시자 창이 자동으로 열리고 빨간 강조가 붙는다.

**이유.** 감독 이벤트 로그와 채팅은 목적이 다르다(자동 수집 vs 사후 검토). 화상 SDK 메시징은 비용이 추가된다.

## 7. 답안은 시험 단위 zip — 2026-07-16

**상황.** 작업형이라 답안에 파일과 긴 글이 섞인다. CSV 하나로는 부족하다.

**선택.** 시험 전체를 zip 하나로 내보낸다. 응시자별 폴더, 문항 × 슬롯별 파일(원본 파일명 유지), Excel에서 바로 열리는 요약 CSV, 응시자 상태 · 이벤트 요약 md. 자동 제출 세션은 별도 폴더로 빼지 않고 요약에 표시만 한다.

**이유.** 채점자는 외부 인력이다. zip 하나 받아 폴더를 열면 되는 구조가 인수인계 비용을 최소화한다.

**트레이드오프.** 과목 간 파일명이 충돌해 답안이 유실되던 버그를 운영 중 발견해 고쳤다.

## 8. 파일 슬롯 저장 경로 — 2026-07-16

**선택.** 답안 파일은 별도 private 버킷에 `세션/문항/슬롯/해시+솔트.확장자`로 저장한다. 해시로 무결성을 자연히 확보하고, 솔트로 같은 파일을 다시 올려도 경로가 겹치지 않는다. 시험 첨부 버킷과 응시자 답안 버킷을 분리해 접근 제어를 다르게 둔다.

## 9. 실습과 실시험은 같은 컴포넌트 — 2026-07-15

**선택.** 환경 체크(듀얼 모니터 · 웹캠 · 화면 공유 · 네트워크 · CPU · 브라우저) → 보안 서약 → 대기실 → 시험창 4단계 위저드를 하나로 만들고, 세션 ID가 있으면 실시험(단계별 결과를 서버에 저장), 없으면 실습(저장 없음)으로 동작한다. 웹캠 · 화면 공유 스트림은 1단계에서 한 번 얻어 부모 컴포넌트가 끝까지 들고 있다.

**이유.** 응시자가 시험 당일 처음 보는 화면이면 안 된다. 실습 링크에서 같은 흐름을 미리 겪게 한다. 스트림을 단계마다 다시 얻으면 권한 팝업이 반복된다.

## 10. 화상은 Agora — 2026-07-14

**상황.** 초기 계획은 다른 화상 SDK였다.

**선택.** Agora Web SDK, 서울 리전, 듀얼 스트림(simulcast). 감독관 그리드는 저해상도로 받고 이벤트 발생 응시자만 고해상도로 확대한다.

**이유.** 100명 규모에서 비용이 크게 낮았고, 무료 사용량으로 첫 회차를 감당할 수 있었다.

## 계획했으나 만들지 않은 것

| 항목 | 상태 | 이유 |
|---|---|---|
| 응시 녹화 저장(Cloudflare R2) | 스키마만 있음 | 시험당 수백 GB 보관 정책이 정해지지 않았고, 실시간 감독만으로 운영이 가능했다 |
| 이메일 초대 · OTP | 제거 | 공용 링크 + 명단 매칭으로 충분했다 |
| 인증서 발급 | 제외 | 시험 응시 · 채점까지가 범위 |
| 서술형 AI 채점 | 제외 | 작업형 전용이라 대상이 없다. export로 외부 위임 |
| 신분증 자동 인식 | 제외 | 업로드 + 관리자 사후 검토. 개인정보 처리 부담을 줄였다 |
